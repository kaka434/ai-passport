## Football Live Board v0.1.0 — 2026-10-21

First release of the football live score board, developed on the
`feature/football-live-board` branch.

- Added a live score board that pulls today's matches over Wi-Fi from the public
  Dongqiudi feed: live matches first, then today's fixtures, then today's finished
  matches, capped at 24 rows, filtered to seven competitions (Premier League, La
  Liga, Serie A, Bundesliga, Ligue 1, Chinese Super League, China League One).
- Added single-match detail with a goal timeline (home left, away right, minute in
  the middle, penalties and own goals marked), formation and eight statistics.
  A match that has not started reads "Match not started" instead of an error.
- Added provisioning without a computer: scan for an SSID and type the password on
  a 6x7 on-screen keyboard, or let the device host an access point and fill a phone
  web page. Working networks are stored in NVS with basic validation.
- Added explicit empty states: when today has no match the board jumps to the
  nearest match day and pins an amber countdown banner; when nothing is scheduled
  within seven days it says so instead of showing a blank list.
- Made every network response streaming, because the C3 has no PSRAM: the list
  response is 1.6 MB and the largest match detail is 37.9 KB while free heap at
  runtime is about 25 KB. Fixed a detail-page parse failure that showed an error
  for every match that had not started, caused by the API returning an empty array
  where the parser only accepted an object.
- Added serial console commands `wifi set/status/clear` and
  `board interval/refresh/detail`, a 60/120/300-second auto-refresh, and a backlight
  dim to 18% after two idle minutes.
- Sized TLS, Wi-Fi, lwIP and the LVGL pool from measured values on this board, with
  the measurements recorded in `docs/reference/kaka/`.

## Football Live Board v0.2.0 — 2026-10-22

Also developed on the `feature/football-live-board` branch. This release fixes two
"cannot see it" problems (early-morning matches, player names) and widens the board
from "today only" to "page backwards and forwards".

- Fixed the board not showing early-morning matches. The `match_list` feed is anchored on the UTC day, so it never returns the Beijing-time 00:00–07:30 window where Champions League and Europa League early kick-offs live; the board now fetches that window from `schedule_list` and merges it in, deduplicated by match id. `schedule_list` omits in-progress matches entirely, so it supplements `match_list` rather than replacing it. The backfill is throttled: every refresh tops it up before 07:00, because the latest early kick-off may still be running, and once per day after that, which keeps steady-state traffic at 264 KB per refresh.
- Fixed every player name in the match detail showing as `?`. The detail endpoint escapes all Chinese text as `\uXXXX`, and the escape branch only accepted ASCII, downgrading every other code point to `?`; it now decodes to UTF-8 properly and handles surrogate pairs. Zero-width characters such as U+200B no longer render as a stray question mark.
- Raised the finished-match cap from 4 to 14 and the row capacity from 24 to 40. A single Champions League match day has nine or ten early-morning fixtures, and a Saturday has 30 whitelisted matches, both of which the old limits truncated.
- Added day paging on the scores page: press Up on the first row to replay the previous day (header becomes `Replay MM-DD`), press Down on the last row to move forward a day (`Tomorrow MM-DD`), up to seven days ahead. Backfilling the early-morning window means today is no longer empty, which stopped the old "jump to the next match day" fallback from firing; future matches are now reached by paging forward. A day other than today is fetched once and cached, paging back to it downloads nothing, and a result that lands after the user has paged away is dropped instead of flashing the previous list first.
- Added the Champions League and the Europa League to the league whitelist, bringing the board to nine competitions. Matching stays exact, so the Conference League, the women's Champions League, the UEFA Youth League, and the AFC Champions League Elite are still rejected.
- Added a 2.2 s pixel-art GOAL splash on cold boot: eight frames of a ball curling into the net with a `GOAL!` burst. Frames are L8 grayscale in flash, so it costs 600 KB of flash and no RAM, and it is skipped on key wake.
- Added auto screen-off (always on / 30 / 60 / 120 seconds, default 60) and screen brightness (25/50/75/100%, default 100%) to the settings page and the serial console. Screen-off only turns the backlight off; fetching keeps running, so the panel shows fresh scores the moment a key wakes it.
- Made the settings menu act on key press instead of waiting out the 180 ms click window, and repaint only the selected row instead of rebuilding the whole page. Key repeat no longer collapses two quick presses into an unhandled double-click.
- Hardened score fetching: a failed fetch is retried once after 1.2 s and then waits 30 s instead of idling a whole refresh interval, and failure logs now report free heap and the largest free block so TLS failures can be told apart from network failures.
- Fixed the banner label truncating to "Next ma...": DOTS mode reserves the ellipsis cell before laying out text, so five 12 px ideographs need a 72 px label and 70 px cut one off.

## Unreleased

- Fixed the board landing on an empty day and paging to tomorrow after the first refresh of the day. The dawn-window backfill was throttled with a flag that said "already fetched", but every refresh clears the parse buffer, so the dawn rows went with it and the second refresh parsed zero matches for today. The backfill now runs on every refresh - 130 KB buys determinism over a flag that can disagree with the data - retries once in place on failure, and voids the whole refresh rather than publishing a half-day list.

- Cut the intermittent `PK verify failed with error 0x4290` on cold boot by shrinking the LVGL pool from 40 KB to 32 KB. The error decodes to `MBEDTLS_ERR_RSA_PUBLIC_FAILED + MBEDTLS_ERR_MPI_ALLOC_FAILED`, i.e. a failed allocation inside the RSA public operation rather than a bad signature: `esp_crt_bundle` builds a fresh public-key context per chain link, and `mbedtls_rsa_public()` routes through IDF's hardware-MPI wrapper, which computes the Montgomery constant from scratch each time (a 4097-bit scratch number plus a software division). That burst, stacked on the 16 KB TLS in-buffer, the 4 KB out-buffer, the parsed chain and the lwIP/Wi-Fi receive buffers, drained the heap to a few hundred bytes. Measured free heap during an open session rose from about 7.8 KB to about 19 KB, and ten consecutive cold boots went from one certificate failure to none. The 16 KB in-buffer cannot be reduced - the server emits 16,401-byte records and 8 KB fails at the eighth record - so the memory had to come from elsewhere.

- Show team crests on the detail page. The score bar on the goals page grows from 46 px to 68 px to make room for a 32x32 crest above each team name. The stats page drops its formation strip -- it shared `y=0` with the score bar and had been covering it -- and reuses the same crest-bearing score bar, with stat rows moving from 24 px to 22 px pitch and from `y=48` to `y=74`. Crest URLs come from `statistics.team_A.logo` / `team_B.logo` in the detail response. The originals are 150x150 (90 KB decoded, not viable on the C3), so the CDN's `?imageView2/2/w/32` is used instead: across 120 sampled crests p99 was 3295 B and the max 3451 B.

- Added `main/app_png.c`, a minimal hand-written PNG decoder (DEFLATE inflate, all five unfilter modes, palette and tRNS) covering only images up to 32x32, bit depth 8, non-interlaced, colour types 0/2/3/4/6. Sampling 45 crests turned up palette, RGBA and grayscale+alpha variants -- the CDN picks per image, so a decoder that misses any of them leaves a batch of crests as placeholder blocks. lodepng was not used because decoding one 32x32 image needs 4 KB of output plus nearly 3 KB of Huffman tables from the heap, whereas this one needs a single scratch buffer supplied by the caller.

- Added `main/app_crest.c`: two URL-keyed slots, so re-opening the same match does not hit the CDN again. Downloads go through `app_net_fetch_binary()` and share the same HTTP mutex as the match detail, so two TLS sessions never hold 16 KB inbound buffers at once.

- The crest download and inflate buffers are taken from the heap per fetch and returned immediately; only the two 32x32 pixel buffers (4.1 KB) stay in `.bss`. Those two transient buffers add up to 8 KB, and pinning them in `.bss` would cost every TLS handshake 8 KB of headroom -- exactly the cause of the `0x4290` failures fixed in the previous version. Measured `.bss` drops from 94,296 to 86,072 bytes.

- Fixed `detail_task` only pumping crests after `detail_fetch()`: crest URLs come from the detail response, so the UI asks for them only once the response has arrived -- by which time that `detail_fetch()` has long finished and the task is back asleep, swallowing the later request. It now drains the queued crests on every wakeup, and crest requests are enqueued right after a successful `detail_fetch()`, which also lets the serial `board detail <id>` command exercise the whole path.

- Measured: 6/6 cold boots fetched all 25 matches with zero `0x4290`; `board detail 54383914` downloaded and decoded both crests (1108 B and 674 B).

- Fixed matches that have not kicked off showing no crests on the detail page. The decoder was not at fault: the overview response simply has no crests. It measures 187-260 bytes, with `statistics` an empty array, `tendencies` null, and neither team object present. The fix issues a second request to `/data/detail/match/{id}`, which flattens the team data into `matchSample.team_A_logo` / `team_B_logo` -- populated even before kickoff. That document is 5.7 KB with the two fields at offsets 1552 and 1833, so only the first 4 KB are read into a heap buffer that is returned immediately. The request is only made when the overview came back without crests, so live and finished matches never pay for it.

- A cheaper route was tried and rejected: `match_list` carries a logo for every team, fixtures included, so the list parser could keep them and skip the second request. But 40 matches x 2 teams of URLs cost 5.8 KB of static memory, and with it two of six cold boots failed certificate verification with `0x4290` (`.bss` 86,072 -> 91,904), against 0/6 without it. Static memory is exactly the TLS handshake headroom, so one saved request is not worth that trade. Reverting to the zero-static-memory design put `.bss` back at 86,064 bytes and cold boots back to a clean 6/6. (There is no per-team crest endpoint: `/data/team/{id}` and seven other candidate paths all return 404.)

- Measured: `board detail 54389825` (Chinese Super League, Henan vs Beijing Guoan, not yet kicked off) read 4096 bytes from `detail/match` and downloaded plus decoded both crests (2904 B and 2919 B); `board detail 54383914` (finished) issued no fallback request and still took its crests from the overview response.

- Rejected truncated responses: a body shorter than its `Content-Length` is now a failure instead of a half-parsed JSON document that silently published a partial list. Handshake failures now log the resolved address and the wall clock, and connect failures log free heap and the largest free block, so a certificate problem can be told apart from a network or memory one.
